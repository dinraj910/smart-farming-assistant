Proposal

From "a trained model behind a form" to an agent that reasons.

Model 1 (Crop Recommendation) is trained and working. Model 2 (Yield Prediction) is being built. Both are correct engineering — and both are also exactly what dozens of other student projects submit every year. This proposal doesn't replace them; it wraps them in an agentic reasoning layer that adds three things a single classifier structurally cannot do:

Cover crops outside the dataset

Pepper, cardamom, rubber, tapioca — not in any public crop-recommendation dataset. An agent can fall back to real agronomic literature instead of just failing.

Reason over real-time context

Weather, market price, and soil data together — not as separate screens, but combined into one grounded recommendation.

Explain itself

Shows which tools it called and which source it used — transparency a black-box classifier can't offer, and reviewers notice the difference.

Positioning

Model 1 and Model 2 become tools the agent calls, not replaced work. Everything already built stays exactly as valuable — this is additive, not a restart.

01

Research Foundation

This is a live 2025–2026 research area, not a buzzword. Six directly relevant papers, found and read before writing this plan:

Agentic AI with Large Language Models for Precision Farming (2026)

Proposes an LLM as a high-level cognitive controller that processes soil/weather/growth-stage data alongside agronomic knowledge, then coordinates irrigation, fertilization, and crop-protection decisions — arguing that single-task ML models lack the contextual reasoning and multi-objective coordination needed for real farm decisions. Directly supports the core argument of this proposal.

Agentic AI-Based IoT Precision Agriculture Framework (AgriEngineering / MDPI, 2026)

Describes AgroAskAI, a multi-agent reasoning framework for climate adaptation, and explicitly notes that most existing smart-agriculture decision-support systems remain a modular pipeline without real multi-agent coordination — precisely the gap this proposal closes for our project.

Agentic AI-Driven Autonomous Decision Support System for Smart Agriculture (Nature Scientific Reports, 2026)

Combines deep learning, ensemble learning, and explainability techniques (SHAP/LIME) inside an agent-based framework that processes location, soil images, and nutrient levels into adaptive recommendations — validates the "explainable reasoning trace" element of this proposal's UI plan.

Evaluation of Learning-Based Models for Crop Recommendation (MDPI, 2025)

Found that a GPT-2-based model matched or exceeded classical ML/DL accuracy on crop recommendation while also offering natural-language interaction — evidence that adding a language-reasoning layer doesn't have to trade off predictive accuracy.

AgriRegion — Region-Aware RAG for Agricultural Advisory (2025)

Notes that general-purpose RAG frequently gives advice that's scientifically correct in one region but wrong in another due to soil/climate variation, and proposes geospatial metadata injection to keep retrieval region-locked — the exact justification for grounding our RAG layer specifically in Kerala Agricultural University documents rather than generic agricultural text.

Farmer.Chat — Scaling AI-Powered Agricultural Services for Smallholder Farmers (Digital Green, arXiv 2409.08916)

A production RAG-based farmer advisory system built on extension documents and crop tables, with a feedback loop where farmer ratings refine the knowledge base over time — a real-world precedent this proposal's architecture closely mirrors, at much smaller scale.

These six sources should be added to the Literature Study document — they directly support the innovation claim for a review panel.

03

How It Works — Two Real Scenarios

Scenario A — crop IS in the training set

"What should I plant on my 1-acre plot? Soil N=40 P=30 K=35, pH 5.8."

  1. Agent calls Crop Recommendation Model → coconut, 92% confidence
  2. Agent calls Weather Lookup → no near-term risk flagged
  3. Agent calls KAU Knowledge Search for "coconut intercropping Kerala" → retrieves pepper/banana/cocoa companion guidance
  4. Final answer: ML-verified crop + KAU-grounded intercropping plan, both cited
Scenario B — crop NOT in the training set

"Is my land suitable for cardamom?"

  1. Agent checks: cardamom isn't one of the 22 classes the trained model knows
  2. Does not call the classifier — would be a meaningless guess
  3. Calls KAU Knowledge Search directly for cardamom-specific agronomic requirements
  4. Final answer labeled "AI-reasoned from agricultural literature," not "ML-verified" — an honest confidence distinction, not a fabricated one

This is the actual answer to "why can't local vegetables be covered." They can — just not by the same mechanism, and the system says so instead of pretending otherwise.

05

Build Phases

Sequenced so the app has a working fallback at every stage — nothing breaks what already works.

01

Knowledge base construction

Download KAU PoP PDFs for target crops → extract text → chunk (~500 tokens, overlap) → embed → store in pgvector.

02

Tool wrapping

Wrap Model 1, Model 2, Weather, Market as callable functions with clear JSON schemas — no changes to the models themselves.

03

KAU retrieval tool

Semantic search against the pgvector table, wrapped as a tool the agent can call.

04

Agent orchestration loop

Groq client + system prompt (Section 07) + tool-calling loop: LLM decides which tools to call, executes, reasons over results, produces final answer.

05

New endpoint

POST /api/v1/agent/crop-advisory — runs the full loop, returns recommendation + reasoning trace + sources. Existing /crop-recommendation endpoint stays untouched as a fallback.

06

UI updates

Reasoning trace panel, source citations, confidence-tier badges, free-text query box — see Section 06.

Agent Prompts & Tool Schemas

System Prompt

You are Krishi Sakhi, an agricultural reasoning assistant supporting Kerala
farmers. You have access to these tools: crop_recommendation_model,
yield_prediction_model, weather_lookup, market_price_lookup, kau_knowledge_search.

Rules:
1. For crops covered by crop_recommendation_model's known class list, ALWAYS
   call it first and treat its output as your primary, ML-verified answer.
2. For crops NOT covered by the trained model, do NOT guess -- call
   kau_knowledge_search before answering. Never fabricate agronomic advice.
3. Call weather_lookup whenever the question involves planting timing,
   irrigation, or crop protection.
4. Call market_price_lookup whenever the question involves crop selection
   for profit or selling decisions.
5. For intercropping suggestions, call kau_knowledge_search for Kerala
   homestead companion-planting guidance -- do not invent combinations.
6. Clearly label each part of your answer as "ML-Verified" or "AI-Reasoned
   from agricultural literature" -- never blend the two confidence levels.
7. Cite the specific KAU document section whenever kau_knowledge_search is used.
8. If no tool can answer confidently, say so plainly. Do not fabricate.
9. Keep the final answer concise and actionable for a farmer with limited
   technical background.

Honest Feasibility Notes

What to tell your guide alongside the pitch, not instead of it.

Groq's free tier is real but bounded

30 requests/minute is plenty for development and a live demo, not for production scale. Correct framing for a review: "sufficient for our project's scope," not "infinitely scalable."

This is additional scope, not free

Six new build phases on top of an already-full semester plan. Recommend this replaces some of the "Stretch" tier features from the earlier roadmap, not stack on top of everything else.

Multi-agent does not mean multiple LLM calls stacked randomly

The value is in the decision logic (when to trust the classifier vs. fall back to retrieval) -- not in adding LLM calls for their own sake. Keep the system prompt's rules as the actual design artifact to defend in a viva.

Fallback if time runs short

Ship the KAU RAG tool + free-text query as a standalone feature even without the full multi-tool agent loop -- still genuinely novel, still uses real research grounding, smaller build surface.
